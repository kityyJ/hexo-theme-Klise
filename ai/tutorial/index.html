Claude Code Skills 上手：安装官方示例，再把重复任务写成可复用技能

来源与范围

依据 Anthropic 官方 skills 仓库 README 整理，资料核对日期为 2026-10-15。仓库说明页没有单独文章发布日期，因此不编造发布时间。本文讨论 Claude Code 中的技能使用与最小模板。

Skill 是包含说明、脚本和资源的目录。它的价值是把稳定的工作方式保存下来，让助手在合适任务中复用，而不是每次重新解释一长串要求。它也不等于额外权限：写进技能里的操作，仍须受到宿主工具、账户权限和用户授权约束。

用明确任务检验调用

安装后，在请求中点明目标与技能，例如让它按指定技能处理一份没有敏感内容的测试文档。检查输出是否真的符合约定结构；“我会使用某技能”的文字声明，不足以证明生成结果已经满足要求。

如果没有调用预期技能，先核对插件是否安装、任务是否符合技能描述，以及当前宿主是否支持该技能。Claude.ai、Claude Code 与 API 的接入方式不同，不能把一个产品的安装步骤直接套到另一个产品。

最小 SKILL.md 可以这样组织

官方说明中的基础格式是带有 name 与 description 的 Markdown。下面是一个原创的报告检查示例，可在官方模板基础上调整：

描述要写清楚什么时候用，正文要写清楚怎么做。与其堆砌几十条抽象形容词，不如给出一两个可判定的例子和明确输出要求。

用三组输入检查，而不是只看一个成功案例

第一组是正常输入：资料齐全，观察输出结构是否稳定。第二组故意缺少关键日期或来源，检查它是否指出缺口。第三组放入互相冲突的数据，检查它是否识别矛盾，而不是替用户编一个看似完整的答案。

涉及脚本的技能还应审查脚本来源、读取范围和写入行为。测试时使用可丢弃的文件副本，不让一个新技能直接修改唯一原件。

注意不同目录的许可证

官方仓库说明，许多示例采用 Apache-2.0；文档处理目录中的部分技能是 source-available，并不等同于开源许可。复制、改编或分发前应查看具体目录的许可证，不能把整个仓库统一称为随意可用的 Apache 项目。
