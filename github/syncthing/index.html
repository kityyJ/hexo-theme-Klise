Syncthing 双机同步教程：设备配对、文件夹共享与版本保护

2026-10-15 GitHub与开源 JIA
适用范围

依据 Syncthing 官方入门文档与 v2.1.6 发布记录整理，核对日期 2026-10-15。本文以两台电脑之间同步一个测试文件夹为例，先验证，再接入真实资料。

Syncthing 的核心用途是持续同步设备之间的文件，许可证为 MPL-2.0。它能减少手动复制的麻烦，但双向同步也可能把删除操作同步到其他设备，因此第一步应是建立独立的小测试目录，而不是直接共享整个文档盘。

1. 两端安装并记录设备 ID

分别从项目官方发布页或受信任的软件渠道安装，启动 syncthing。官方核心程序默认提供本机管理页面 http://localhost:8384/；界面封装版入口可能不同。不要把管理端口直接暴露到公网。

在两端的 Actions／操作菜单中找到 Show ID／显示 ID。给设备取明确名称，例如书房电脑和笔记本。名称便于识别，真正配对依据是设备 ID；不能只看相似的设备名就接受连接。

2. 互相添加设备

在 A 端选择 Add Remote Device／添加远程设备，填入 B 的 ID；在 B 端重复操作，填入 A 的 ID。两端都认可后，再观察状态是否从断开变成已连接。配置更新需要短暂时间，不要连续重复添加同一设备。

如果一直离线，先确认两端程序都在运行，再检查防火墙与网络限制。设备间连接可能借助发现服务或中继，不能把界面里的“已连接”直接解释成一定只走了局域网。

3. 只共享一个新的测试文件夹

在 A 端新增一个测试文件夹，为它设置清晰名称，并勾选共享给 B。B 接到共享请求后，选择自己的本地保存路径。两台电脑的磁盘路径可以不同，但应对应同一项共享；不要在 B 上误选一个已经装满无关文件的目录。

先放入 hello-sync.txt，等两端都显示同步完成后，在 B 打开它核对内容。再在 A 修改一行，确认 B 更新；然后反向修改一个新的测试文件，确认 A 也收到。这比仅看到设备“在线”更能证明配置有效。

4. 再决定是否需要双向修改

两端都会编辑时，可以使用双向同步。若一端只是分发资料或保留接收副本，先阅读对应文件夹类型的官方说明，再选择发送／接收方向；不要凭名称猜测覆盖规则。

多人同时编辑同一个文档，可能出现冲突副本。先比较内容再整理，不能看到带有冲突标记的文件就全部删除。重要文件接入前，先约定哪端负责编辑、哪端负责归档。

5. 文件版本不能代替独立备份

可在接收端的文件夹设置里启用文件版本控制，并根据保留策略测试旧版本是否可恢复。版本功能针对被同步覆盖或删除的文件，不代表能撤销本机的一切操作，也不能保护同一磁盘损坏。

建议为重要资料另做一份独立备份。只有在空测试目录中验证删除传播，确认自己理解行为后，才逐步扩大同步范围。

验收顺序

设备连接成功 → 测试文件出现 → 修改正确传播 → 冲突可识别 → 旧版本可恢复。缺少后几步时，不宜直接迁移唯一一份资料。
