:::

LocalSend 是 Apache-2.0 许可的开源跨平台文件分享工具，可以在本地网络通过 HTTPS 传输文件与文字，不依赖第三方存储中转服务器。它适合电脑与手机之间临时传照片、文档和小批量资料。

## 先完成一次最小传输
在发送端和接收端分别从官方列出的应用商店或软件渠道安装。两台设备接入同一可信本地网络，同时打开 LocalSend，记录各自显示的设备名称。

发送端先只选择一张不含隐私的测试图片，选择正确的接收设备；接收端确认请求并选择保存位置。完成后打开图片核对，确认是正确文件，而不只是界面显示了传输进度。

大批量文件传输前先做这一步，可以同时发现权限、接收路径和设备选择错误。

## 情况一：完全看不到另一台设备
先确认两端应用都在前台，手机已允许本地网络相关权限，电脑没有把应用的本地网络通信全部拦截。设备即使连着相同名称的 Wi-Fi，也可能处于访客网络或不同隔离区域，未必能相互访问。

如果使用家用路由器，检查是否开启 AP 隔离或访客隔离。只在自己管理、且确认需要设备互通的网络调整设置；公共网络由管理员限制时，不要试图绕过。

## 情况二：能发现设备，点发送却失败
官方 README 给出的入站端口是 TCP、UDP 的 53317。按系统防火墙给 LocalSend 放行相应的可信本地网络通信，而不是关闭整个防火墙。网络中还有 VPN、代理或安全软件时，也应检查它们是否改变了局域网路由。

重新测试同一张小图片。如果小文件稳定、大文件中断，再检查设备是否休眠、剩余空间是否足够，以及接收端保存目录是否可写。

## 情况三：对方说收到了，自己找不到文件
在接收端查看实际保存目录和应用接收记录，按文件名与大小核对。手机系统的相册、下载目录和文件管理器并不是同一个入口；收到文档也不一定会出现在照片相册里。

对重要文件，传输后至少打开一次；资料很多时可按文件数量、大小或校验值确认，而不要把“发送完成”直接等同于长期备份成功。

## 升级与兼容性
当前 README 对不同平台列出了最低系统版本；旧设备不应盲目安装最新包。项目还提醒应用自身不提供统一自动更新机制，使用应用商店或软件包管理器渠道更便于后续维护。

::: tip 使用习惯
给设备设置容易辨认的名称；发送前核对接收设备；私密文件只向自己确认的设备发送；传完后检查内容和保存位置。
:::
