Immich 是可自行托管的照片与视频管理应用，包含手机备份、相册、搜索和多用户功能，仓库采用 AGPL-3.0 许可证。它适合想把相册服务放在自己设备上的用户，但服务器里有一份照片，并不等于已经完成可靠备份。

## 先准备独立目录和存储
确认主机满足官方硬件要求并已安装 Docker Engine 与 Compose 插件。先运行 `docker compose version`，不要把旧的 `docker-compose` 命令与新插件混用。为新实例建立独立目录，并确认照片所在磁盘有足够空间；已有实例不要直接覆盖原配置。

```bash
mkdir immich-app
cd immich-app
curl -fL -o docker-compose.yml https://github.com/immich-app/immich/releases/latest/download/docker-compose.yml
curl -fL -o .env https://github.com/immich-app/immich/releases/latest/download/example.env
```

以上命令仅用于全新的空目录。下载后先阅读文件，确认文件来自官方仓库；升级现有实例时，应先看升级说明与备份要求。

## 编辑 .env，区分两类数据
`UPLOAD_LOCATION` 是照片与视频的存放位置，应选真实、稳定挂载的数据目录。`DB_DATA_LOCATION` 是数据库目录，官方说明不支持把数据库放到网络共享路径；不要因为照片盘是 NAS，就把数据库目录也随手指向同一网络共享。

把默认 `DB_PASSWORD` 换成足够长的随机值，按官方建议使用字母与数字；设置自己的 `TZ`。需要固定版本时可核对发布页后设置 `IMMICH_VERSION`，不要在不知道迁移要求的情况下跨大版本升级。

## 启动并确认服务状态
```bash
docker compose config --quiet
docker compose up -d
docker compose ps
docker compose logs --tail=100
```
`config --quiet` 用于先检查配置结构。若容器持续重启，先看日志中的首个具体错误，检查目录权限、数据库目录与磁盘空间，再重试；不要反复删除数据库目录来碰运气。

## 用测试照片做一次完整验收
先按官方安装后说明创建账户，让手机连接服务器，只选择一个小测试相册。上传几张照片和一个短视频，核对数量、拍摄日期、视频播放与原文件下载；再从另一台设备登录同一账号，确认能够读取。

测试通过后再逐步加入真实相册。若手机退出后上传暂停，先检查系统后台与电池策略，不能仅凭网页里出现缩略图就认定全部原片已经安全保存。

## 上线后保留三份恢复依据
照片原文件、数据库备份、部署配置分别保存。数据库应使用官方支持的一致性备份流程，不把复制正在写入的数据库目录当作已验证的恢复方案。定期用一小组测试素材检查下载与恢复，不要直接拿唯一一份家庭照片验证删除和回滚。

升级前先备份，阅读目标版本说明，并留出维护窗口。若需要对外访问，再单独配置 HTTPS、访问控制与备份策略，避免刚部署就把管理入口随意公开。
